## ImagePicker

Является оберткой компоненты `FilePicker`.

Управляемый выбор одного файла-изображения с проверкой MIME-типа и необязательного ограничения размера. Значение хранит родитель. компонент не мутирует `value` и не знает о бизнес-обязательности файла. 

Компонент отвечает за превью: создание и освобождение blob-URL из value, рендер области превью в одном из трёх состояний (пусто / изображение / ошибка декодирования), замену изображения заглушкой по onError и уведомление onValidationChange(IMAGE_ERROR) при ошибке декодирования. Ошибка декодирования не отменяет выбор: файл уже передан в onChange до того, как браузер попытался его отрисовать.

### Props

| Prop | Тип | Обязательный | Назначение |
| --- | --- | --- | --- |
| `value` | `File \| null` | Да | Выбранный файл-изображение или `null`, если файла нет. |
| `onChange` | `(file: File \| null) => void` | Да | Передаёт валидный файл после проверки или `null` при удалении. |
| `acceptedTypes` | `readonly string[]` | Да | Допустимые MIME-типы. Используются для `accept` и точной проверки `file.type`. |
| `maxSizeBytes` | `number` | Нет | Максимальный размер в байтах включительно. Если не задан, размер не ограничивается. |
| `disabled` | `boolean` | Нет | Блокирует выбор и удаление файла. |
| `error` | `string` | Нет | Внешняя ошибка формы; отображается, если локальной ошибки нет. |
| `onValidationChange` | `(error: string \| null) => void` | Нет | Сообщает локальную ошибку проверки или `null` при её очистке. |

### Как подключить

```tsx
import { useState } from 'react'
import { ImagePicker } from '@/shared/ui/ImagePicker'

export function BasicExample() {
    const [file, setFile] = useState<File | null>(null)
    const [localError, setLocalError] = useState<string | null>(null)
    const [submitError, setSubmitError] = useState<string | null>(null)

    return (
        <ImagePicker
            value={file}
            onChange={setFile}
            acceptedTypes={['image/png', 'image/jpeg', 'image/webp']}
            maxSizeBytes={2 * 1024 * 1024}
        />
    )
}
```

### Поведение

- MIME-тип и размер проверяются до вызова `onChange`. В примере допускаются JPEG и PNG размером до 2 097 152 байт включительно.
- Невалидный файл не заменяет предыдущий: `onChange` не вызывается, локальная ошибка отображается и передаётся через `onValidationChange`. Предыдущее превью остаётся видимым.
- Успешный выбор очищает локальную ошибку и сообщает `onValidationChange(null)`. Кнопка «Удалить файл» также очищает локальную ошибку, вызывает `onChange(null)` и убирает превью вместе с blob-URL. После удаления тот же файл можно выбрать снова.
- Отмена диалога сохраняет значение, состояние ошибки и текущее превью.
- Внешняя замена файла пересоздаёт `previewUrl`: старый blob-URL освобождается через `URL.revokeObjectURL`, для нового файла создаётся новый. Сброс `value` в `null` очищает `previewUrl` и `erroredUrl`. При замене `value` на другой файл `erroredUrl` не сбрасывается — пользователю это не видно (`erroredUrl !== previewUrl` ⇒ `hasError === false`), но в `state` остаётся уже отозванный blob-URL. `onValidationChange` при внешней замене или сбросе value компонент не вызывает: если была ошибка декодирования, родитель должен очистить её сам. Подтверждение родителем обычного выбора или удаления не дублирует уведомление; смена ссылки callback сама по себе его не вызывает.
- Область превью рендерится всегда. Внутри переключаются три состояния: «нет изображения» — заглушка с `aria-hidden="true"`; «изображение» — <img src={previewUrl} className={styles.image} with object-fit: contain>; «ошибка декодирования» — заглушка с `role="alert"` и текстом `IMAGE_ERROR`.
- Файл, прошедший проверку MIME/размера, но не декодируемый браузером (например, повреждённый PNG), уже передан в `onChange` — `ImagePicker` не может отклонить его на этапе валидации. После монтирования <img> кидает `onError`: изображение заменяется заглушкой, а `onValidationChange` получает `IMAGE_ERROR`. Ошибка не заменяет `value` и не блокирует повторный выбор другого файла.
- {<img>} имеет `key={previewUrl}`, поэтому при смене файла монтируется новый узел и обработчики старого не «протекают» на новый. В `onError` сравнивается `e.currentTarget.getAttribute('src')` с текущим `previewUrl`: события устаревшего <img> игнорируются, поэтому запоздалая ошибка старого файла не влияет на новый. `erroredUrl` очищается при сбросе `value` в `null`, а при замене файла — через сравнение с новым `previewUrl` в `hasError`.
- Внешний `error` остаётся под управлением родителя и показывается, только если нет локальной ошибки валидации от `FilePicker`. Ошибка декодирования (`IMAGE_ERROR`) живёт в области превью и на приоритет `error` не влияет — `FilePicker` про неё не знает. Ошибка связана с полем через `aria-describedby`; непустая ошибка включает `aria-invalid`.
- Ошибки двух источников не склеиваются: `IMAGE_ERROR` показывается в области превью, ошибка валидации/`error` — текстом под полем. Если возникли обе (например, `error` от родителя при уже показанной заглушке декодирования), пользователь увидит два сообщения; компоненты не согласуют приоритет между собой.
